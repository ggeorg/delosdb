DelosDB overlay: promote consolidated Gen2 materialized CURRENT scans

Decision:
- Promote the consolidated materialized CURRENT decoder to normal Gen2 behavior.
- Remove the old Gen2 materialized double-decode branch.
- Keep streaming bulk scan experimental and unchanged.

Production change:
- Gen2-A1/CURRENT materialized scans always instantiate MaterializedCurrentScanDecoder.
- The legacy materialized path:
    decodeDirectory()
    -> decodeGen2A1Current()
    -> visibleGen2CurrentOrHistory()
  is removed from scanVisibleAt().
- The singlePassGen2CurrentScan() selector helper is removed.
- The promoted decoder retains:
    one CURRENT fetch/decode
    reusable CURRENT RawStore template
    CURRENT kind/format validation
    lazy creator transaction fetch for uncommitted CURRENT
    lazy predecessor/hint fetch only for HISTORY fallback
    payload cloning for materialized VisibleRow ownership

Correctness:
- Gen2-C1 visibility/history/rollback coverage now exercises the promoted default directly.
- Gen2-C3 projected-current/history coverage now exercises the promoted default directly.

Unchanged:
- StreamingBatchScan remains experimental.
- Streaming eligibility and streaming-specific flags are unchanged.
- Projected-current-read remains experimental/default OFF.
- RowLocation costing remains normal/default ON.
- SQL semantics, MVCC visibility rules, durable formats, RawStore WAL/undo/recovery,
  and benchmark thresholds are unchanged.

Evidence supporting promotion:
- Raw two-column TABLE_SCAN: 4.271132 ms -> 1.701018 ms (2.51x faster, -60.17%).
- Same TABLE_SCAN and canonical GROUP_HIGH_CARD plan shapes.
- Semantic fingerprints matched.
- JFR removed the old directory/template hot allocation sites and reduced GC pressure.
- Canonical SERVER/8c stable first-six runs:
    GROUP_LOW_CARD  882.1 -> 1065.0 q/s (+20.7%)
    GROUP_HIGH_CARD 974.4 -> 1073.1 q/s (+10.1%)
- SERVER scan-ON semantic oracle matched all engines/runs.
- Later SERVER runs suffered broad environmental drift across comparison engines, so
  promotion is based on the consistent Gen2 direction plus the clean raw/JFR attribution,
  not on inflated cross-engine ratios from those late runs.
