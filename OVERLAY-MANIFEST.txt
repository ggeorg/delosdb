DelosDB overlay: align canonical benchmark RowLocation costing with production

Purpose:
- Fix stale benchmark forwarding that defaulted physical Gen2 RowLocation costing to false
  even after that cost model was promoted to normal/default-ON production behavior.
- Make canonical F07/F11/F12/F13 read workloads measure the actual current Gen2 architecture.
- Preserve explicit false only for diagnostics that intentionally compare the retired legacy cost.

Evidence:
- Previous canonical F07 with stale cost=false:
    Gen2 ~295.8 tx/s, ~26.7% PostgreSQL.
- Corrected canonical F07 with cost=true:
    Gen2 863.14 tx/s
    Heap 1113.68 tx/s
    PostgreSQL 1114.70 tx/s
    Gen2/PostgreSQL 77.43%
    Gen2/Heap 77.50%
    Gen2 IQR/median 4.39%
    Gen2 max/min 1.062x
    semantic oracle matched.
- Throughput improvement vs stale F07 baseline: ~2.92x (+192%).

Harness changes:
- DelosJdbcCrossEngineConcurrency.mvccPhysicalRowLocationCostEnabled() default false -> true.
- Canonical F07 explicitly sets mvccPhysicalRowLocationCost=true.
- F07 sentinel requires the summary marker:
    MVCC physical RowLocation cost enabled: true
- Canonical F11 mixed reader/writer explicitly sets true.
- Canonical F12 long-reader/writer explicitly sets true.
- Canonical F13 realistic transaction explicitly sets true.
- F01-F06 already explicitly used true and are unchanged.
- Diagnostics that explicitly set false remain able to test the legacy model.

What this does NOT change:
- No production storage/optimizer code.
- No RowLocation cost formula.
- No SQL/workload definitions or thresholds.
- No semantic oracle behavior.
- No RawStore, MVCC visibility, WAL, undo, recovery, vacuum, or durable formats.

Decision:
- The old F07 ~27% PostgreSQL score is retired as stale-harness evidence.
- Correct current canonical F07 is 77.43% PostgreSQL.
