DelosDB Gen2-C3 F06 reusable CURRENT scan-template experiment

Purpose
-------
Measure whether per-row Gen2 CURRENT fetch-template/DataValueDescriptor construction is a
major part of the remaining F06 table-scan/materialization deficit after the accepted
single-pass CURRENT decode experiment.

Production behavior
-------------------
Default behavior is unchanged. The new experiment is OFF unless:
  -Ddelosdb.experimental.mvccGen2SinglePassCurrentScan.enabled=true
  -Ddelosdb.experimental.mvccGen2ReusableCurrentScanTemplate.enabled=true

Experiment
----------
For scanVisibleAt() only, build one Gen2 CURRENT RawStore fetch template per scan and
reuse it across CURRENT slots. Payload values are still cloned into each VisibleRow,
so row ownership/retention semantics remain unchanged. Non-scan point reads and mutation
paths continue to allocate their own decode template.

Explicitly unchanged
--------------------
- RawStore format / persistence
- MVCC visibility rules
- history fallback
- payload clone semantics
- optimizer costing
- GROUP BY and sort
- projected-current read experiment
- page-local prefetch
- WAL / undo / recovery
- default production behavior

Pre-delivery checks
-------------------
- DelosJdbcCrossEngineConcurrency.java compiled with javac against delosTestSupport sourcepath.
- MvccRawStoreFormat.java and MvccRawStoreTable.java compiled with javac against a flattened
  repository main-source tree plus generated release SanityState.
- scanVisibleAt() remains below the repository 100-line method limit (98 lines).
- ZIP integrity, duplicate-entry and SHA-256 checks performed.
