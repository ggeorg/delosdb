DelosDB Gen2-C3 F06 group-input JFR HotSpot logging fix

Purpose
-------
Fix the Phase-2O diagnostic harness so HotSpot LogCompilation arguments are
configured on the JavaExec task before execution rather than being added from
doFirst. This preserves the existing Heap/MVCC raw two-column TABLE_SCAN probe
and makes the expected per-provider compilation logs reliable.

Changed repository files
------------------------
- delosdb-tests/build.gradle
- delosdb-tests/src/delosTestSupport/java/io/github/ggeorg/delosdb/benchmark/jdbc/DelosJdbcCrossEngineConcurrency.java

Behavior
--------
- Configures -XX:+LogCompilation and the provider-specific -XX:LogFile during
  normal JavaExec configuration.
- Keeps JFR stackdepth configuration unchanged.
- Adds a fail-fast runtime check proving the expected HotSpot logging arguments
  reached the provider JVM before fixture construction/profile work begins.
- Keeps the existing post-run requirement that the HotSpot log exists and is
  non-empty.

Not changed
-----------
- No production storage/MVCC/RawStore code.
- No SQL, plan, fixture, warmup, profile duration, or semantic-oracle changes.
- No GROUP BY, join, sort, projection, or scan implementation changes.
- No benchmark thresholds are changed.
