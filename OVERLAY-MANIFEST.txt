DelosDB overlay: canonical F07 physical RowLocation-cost candidate wiring

Purpose:
- Test whether the canonical F07 SERVER regression is caused by stale benchmark plumbing
  that still forces the retired legacy RowLocation/base-fetch cost model OFF.
- Reuse the existing canonical six-engine F07 fitness/sentinel.
- Change no production code and add no new benchmark contract.

Critical discrepancy found in preserved evidence:
- Canonical F07 summary:
    MVCC physical RowLocation cost enabled: false
    Gen2 ~295.8 tx/s
- Fast sustained q3/q20 diagnostics:
    MVCC physical RowLocation cost enabled: true
    Gen2 ~884.7-898.3 tx/s
- q3 vs q20 differs only ~1.5% for Gen2, falsifying synchronized-interval granularity
  as the source of the ~3x canonical discrepancy.

Historical context:
- Physical Gen2 RowLocation/base-fetch costing was already validated and promoted to
  normal/default-ON behavior.
- DelosJdbcCrossEngineConcurrency still defaults its benchmark forwarding property to false,
  and canonical F07 never explicitly set it.
- Therefore canonical F07 has been overriding the promoted storage default with stale legacy behavior.

Harness change:
- Existing runDelosGen2C3SortFitness now accepts:
    -Pdelosdb.benchmark.mvccPhysicalRowLocationCost=true|false
- Default remains false in this candidate harness so the preserved canonical baseline remains
  reproducible.
- runDelosGen2C3SortSentinel validates the exact RowLocation-cost marker in the summary.

Canonical F07 shape remains unchanged:
- six-engine SERVER matrix
- 8 clients
- 10,000 rows
- SORT_FULL
- FULL_INDEXED
- 8 runs
- transactionsPerClient=3
- 2s minimum warmup
- 5s minimum measured duration
- SQL semantic oracle ON

What this does NOT change:
- No production source.
- No optimizer cost formula.
- No sort implementation.
- No MVCC scan/decode path.
- No workload SQL, thresholds, or target matrix.
- No projected-current setting unless separately requested.

Decision:
- If enabling the already-promoted RowLocation cost restores F07 materially toward the
  sustained diagnostic throughput, the canonical F07 baseline was measuring stale legacy
  optimizer behavior and must be corrected before further F07 performance work.
