DelosDB Gen2-C3 F04 stable-statistics JFR falsification overlay

Purpose
-------
Add a diagnostic-only switch to refresh statistics for the F04 JOIN_INDEXED_1TO1
base and dimension tables before measurement. The Phase 2Y server-JFR task can
then be rerun under otherwise identical conditions to determine whether the
Heap-vs-Gen2 operator divergence is caused by statistics/plan state.

Changed files
-------------
delosdb-tests/build.gradle
delosdb-tests/src/delosTestSupport/java/io/github/ggeorg/delosdb/benchmark/jdbc/DelosJdbcCrossEngineConcurrency.java

Diagnostic property
-------------------
Gradle: -Pdelosdb.f04.refreshSimpleJoinStatistics=true
Worker: delosdb.benchmark.crossEngineConcurrency.refreshSimpleJoinStatistics=true

Behavior
--------
When enabled for the dedicated Delos Heap/MVCC DRDA F04 1:1 diagnostic, the
fixture explicitly invokes SYSCS_UTIL.SYSCS_UPDATE_STATISTICS for the base and
join-dimension tables before the timed workload. The setting is forwarded to
workers and recorded in summary/profile evidence.

Not changed
-----------
No production engine code.
No optimizer cost model.
No join implementation.
No B-tree/MVCC implementation.
No benchmark thresholds or workload SQL.
No canonical F04 task behavior unless this diagnostic property is explicitly set.
