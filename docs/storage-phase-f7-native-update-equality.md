# Storage Phase F7 — native UPDATE equality

F7 moves the first UPDATE proof off the transitional SQL bridge and onto the
native Derby execution seam.

Target SQL:

```sql
UPDATE APP.T SET value = 'beta' WHERE id = 1
```

Execution shape:

```text
Derby parser / binder / optimizer
  -> generated activation
  -> GenericResultSetFactory.getUpdateResultSet(...)
  -> provider-aware metadata branch
  -> DelosUpdateResultSet
  -> Derby source row with before/after columns
  -> DelosTableScanResultSet current DelosRowIdentity
  -> EngineMvccTableAccess.update(...)
```

The proof keeps the existing generated bytecode shape. It does not add a new
`ResultSetFactory` interface method, does not change `FromBaseTable.generate()`,
and does not change `AsmJava`.

The update source row remains Derby-owned. Derby computes the SET replacement
values; `DelosUpdateResultSet` only extracts the after-column half of the source
row and sends it to the provider-owned table-access mutation seam.

The mutation identity remains provider-owned. `DelosTableScanResultSet` carries
the current `DelosRowIdentity` from the native scan row; F7 does not derive row
identity from SQL text or from Derby heap `RowLocation`.

F7 does not add any new bridge SQL route or regex route. The smoke proof resets
`VersionedStorageSqlBridge` diagnostics before the prepared UPDATE and asserts
that `VersionedStorageSqlBridge.tryExecute(...)` was not called for the native
UPDATE proof path.
