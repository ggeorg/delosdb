# Storage Phase G2 — native BETWEEN predicates

Phase G2 proves that SQL `BETWEEN` predicates execute through the native Derby
execution path for `delos_mvcc` tables.

The important design point is that Derby lowers `BETWEEN` into ordinary range
qualifiers before the table scan reaches `DelosTableScanResultSet`.  Therefore
G2 does not add a separate bridge route and does not introduce a new SQL-text
classifier.  It reuses the native G1 range predicate translation and proves the
SQL surface:

```sql
SELECT * FROM APP.T WHERE ID BETWEEN ? AND ?
SELECT * FROM APP.T WHERE ID BETWEEN ? AND ? AND KIND = ?
```

The verified path remains:

```text
prepared SELECT
  -> Derby parser / binder / optimizer
  -> generated activation
  -> GenericResultSetFactory.getTableScanResultSet(...)
  -> DelosTableScanResultSet
  -> Derby range Qualifier[][] generated from BETWEEN
  -> DelosPredicate range filters
  -> EngineMvccTableAccess.scan(...)
  -> Derby ExecRow materialization
```

Constraints:

```text
No new bridge SQL route.
No regex route.
No generated bytecode shape change.
No source/doc token report guard.
```
