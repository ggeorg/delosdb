# Storage Phase F8 — bridge bypass strategy

F8 completes the Phase F correction that stopped expanding
`VersionedStorageSqlBridge` as a production SQL executor.

The wrong design would try to decide, inside `EmbedStatement`, whether a SQL
string targets a metadata-backed `delos_mvcc` table. That is still pre-parse and
pre-bind. It would require a second parser/catalog lookup path and would repeat
the bridge mistake.

The F8 design is intentionally simpler:

```text
EmbedStatement
  -> if native mode is enabled: bypass VersionedStorageSqlBridge.tryExecute(...)
  -> Derby parser / binder / optimizer / generated activation
  -> native ResultSetFactory branches added in F4-F7
```

In short, native mode bypasses bridge interception globally. It does not inspect TableDescriptor before parse and it does not try a per-table pre-parse bypass.

The old bridge remains available only as transitional compatibility/test mode
scaffolding. During the Phase F transition, earlier C/D smokes still use that
compatibility path to prove the historical bridge contracts, while the native
F4-F7 paths assert that their prepared execution does not call
`VersionedStorageSqlBridge.tryExecute(...)`.

F8 adds two explicit bridge-control properties on `VersionedStorageSqlBridge`:

```text
delosdb.storage.nativeMode=true
  -> bypass the EmbedStatement bridge hook globally

delosdb.storage.sqlBridge.compatibility=true
  -> keep the transitional bridge available when native mode is not enabled
```

The F8 smoke proves both sides:

```text
native mode + compatibility property present
  -> CREATE TABLE ... USING delos_mvcc runs through Derby, not the bridge

compatibility mode without native mode
  -> the old bridge route remains explicitly available
```

This leaves the target architecture unchanged:

```text
SQL
  -> Derby JavaCC parser
  -> Derby binder / metadata
  -> Derby optimizer
  -> generated activation
  -> existing ResultSetFactory method family
  -> provider-aware native branch
  -> Delos result set / Delos table access
```

F8 does not add a new bridge SQL route, regex route, generated bytecode method,
or `ResultSetFactory` interface method.
