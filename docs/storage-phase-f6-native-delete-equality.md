# Storage Phase F6 — native DELETE equality

F6 lands the first native DELETE path for `delos_mvcc` catalog tables.

Target SQL:

```sql
DELETE FROM APP.T WHERE ID = 1
```

The execution shape is intentionally narrow:

```text
Prepared Derby DELETE
  -> generated activation
  -> GenericResultSetFactory.getDeleteResultSet(...)
  -> provider-aware catalog lookup
  -> DelosDeleteResultSet
  -> DelosTableScanResultSet equality predicate extraction
  -> EngineMvccTableAccess.scan(...)
  -> DelosRowIdentity
  -> EngineMvccTableAccess.delete(...)
```

The generated bytecode shape stays unchanged.  There is no
`getDelosDeleteResultSet(...)` method, no `FromBaseTable.generate()` change, and
no `AsmJava` change.

`DelosDeleteResultSet` does not parse SQL.  It reuses the native
`DelosTableScanResultSet` source already produced by the Derby compiler and
optimizer for the DELETE source tree.  That source owns the `Qualifier[][]` to
column-name predicate translation from F4.  F6 uses the resulting equality
predicate to scan the provider-owned MVCC table, reads the `DelosRowIdentity`
from each scanned row, and calls `EngineMvccTableAccess.delete(...)`.

The branch is property-gated for the proof.  It does not add a new bridge SQL
route and does not add any new bridge SQL route or regex route.

The smoke proof asserts that the prepared DELETE path does not call
`VersionedStorageSqlBridge.tryExecute(...)`.  It seeds rows through the F5 native
INSERT path, deletes one row through the F6 native DELETE path, and reads back
through the F4 native SELECT equality path to prove that the target row is gone
and the non-matching row remains visible.

F6 intentionally does not cover deferred deletes, triggers, foreign-key checks,
cascade deletes, range predicates, or positioned deletes.  Those stay outside
this proof slice.
