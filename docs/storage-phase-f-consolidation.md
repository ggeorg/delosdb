# Storage Phase F consolidation

F0/F1a through F8 are closed.

Phase F moved `delos_mvcc` from transitional bridge execution into Derby's
native compiler/executor path. The bridge remains compatibility/test scaffolding,
but production MVCC SQL expansion should now happen behind Derby parse, bind,
optimization, generated activation, `GenericResultSetFactory`, and Delos-owned
result sets.

## Closed slice

```text
F0/F1a — freeze bridge expansion and confirm parser-owned USING provider syntax
F2.1    — persist storageProviderName through nullable SYSTABLES.STORAGEPROVIDER
F2.2    — resolve provider metadata from LanguageConnectionContext + tableName
F3.1    — prove provider-aware ResultSetFactory branch point
F3.2    — add DelosTableScanResultSet skeleton behind existing factory shape
F4      — native SELECT equality through DelosTableScanResultSet

```

## Native Derby execution path now covers

```text
SELECT equality
INSERT
DELETE equality
UPDATE equality
```

All four proof paths use prepared Derby execution and assert that
`VersionedStorageSqlBridge.tryExecute(...)` is not called for the native path.

## Bridge status

Bridge interception is globally bypassed in native mode at `EmbedStatement`.
The bridge is not disabled by doing pre-parse provider metadata lookup. That
would re-create a parallel parser/catalog path before Derby has parsed the SQL.

`VersionedStorageSqlBridge` remains only as explicit compatibility/test
scaffolding during the transition.

## Cleanup status

`scripts/delete-stale-storage-smoke-dbs.sh` keeps named cleanup entries for every
Phase F smoke database. The script must stay explicit: no wildcard `rm -rf`
cleanup patterns.

