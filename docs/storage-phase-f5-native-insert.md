# Storage Phase F5 — native INSERT

F5 moves the first DML write off the transitional SQL bridge and onto the native
Derby compiler/executor path.

Target SQL:

```sql
INSERT INTO APP.T VALUES (1, 'alpha')
```

Verified flow:

```text
Derby parser / binder / optimizer
  -> generated activation
  -> GenericResultSetFactory.getInsertResultSet(...)
  -> provider-aware catalog lookup
  -> DelosInsertResultSet
  -> source ExecRow values
  -> DelosNativeTableRegistry.NativeExecutionTableAccess.insert(...)
  -> DelosRow
  -> EngineMvccTableAccess.insert(...)
```

The branch is property-gated for the proof.  It does not add a new
`ResultSetFactory` interface method, does not change generated bytecode shape,
and does not add any new bridge SQL route or regex route.

What is intentionally narrow:

```text
- INSERT VALUES only.
- No generated-column expansion beyond the existing Derby source row.
- No INSERT SELECT proof yet.
- No trigger or constraint expansion beyond the existing focused smoke shape.
```

The smoke creates the Derby catalog table through prepare/constant-action, sets
up the temporary provider-owned table through the existing transitional bridge,
then proves the prepared INSERT path itself does not call
`VersionedStorageSqlBridge.tryExecute(...)`.  Readback uses the F4 native SELECT
equality path.

Result: F5 native INSERT landed.
