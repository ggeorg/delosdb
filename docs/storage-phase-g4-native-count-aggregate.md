# Storage Phase G4 — native SELECT COUNT(*)

G4 proves that a provider-backed `delos_mvcc` table can execute:

```sql
SELECT COUNT(*) FROM APP.T
```

through Derby native execution rather than the transitional SQL bridge.

The execution path is deliberately ordinary Derby aggregation:

```text
Derby parser / binder / optimizer
  -> generated activation
  -> GenericResultSetFactory.getTableScanResultSet(...)
  -> DelosTableScanResultSet
  -> EngineMvccTableAccess.scan(...)
  -> Derby ScalarAggregateResultSet / CountAggregator
  -> JDBC COUNT(*) result
```

G4 does not add a Delos-specific count shortcut.  The native Delos result set
supplies rows; Derby's existing scalar aggregate consumes those rows and computes
`COUNT(*)`.

G4 adds a dedicated proof gate:

```text
delosdb.storage.phaseG4.nativeCountAggregate
```

When the gate is enabled and the target table has provider `delos_mvcc`,
`DelosTableScanResultSet` can provide the source scan for `COUNT(*)` queries.
The smoke proves both an unfiltered count and an equality-filtered count through
prepared JDBC statements.

G4 does not add a bridge route, regex route, generated bytecode change, or
`ResultSetFactory` interface change.
