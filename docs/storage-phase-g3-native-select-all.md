# Storage Phase G3 — native SELECT * full scan

G3 proves that a provider-backed `delos_mvcc` table can execute:

```sql
SELECT * FROM APP.T
```

through Derby native execution rather than the transitional SQL bridge.

The execution path remains the Phase F/G native path:

```text
Derby parser / binder / optimizer
  -> generated activation
  -> GenericResultSetFactory.getTableScanResultSet(...)
  -> DelosTableScanResultSet
  -> EngineMvccTableAccess.scan(..., empty filters, DelosProjection.all())
  -> Derby ExecRow materialization
```

G3 adds a dedicated proof gate:

```text
delosdb.storage.phaseG3.nativeSelectAll
```

When the gate is enabled and the target table has provider
`delos_mvcc`, `DelosTableScanResultSet` accepts an empty `Qualifier[][]` as a
real full table scan. Earlier predicate gates continue to require pushed
qualifiers unless G3 is explicitly enabled.

G3 does not add a bridge route, regex route, generated bytecode change, or
`ResultSetFactory` interface change.
