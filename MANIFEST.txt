DelosDB Gen2-C3 F05 covering-join control overlay

Purpose
-------
Separate non-covering base-row materialization from shared relational join
execution on the current Gen2-C3 F05 three-way selective workload.

Workloads
---------
JOIN_3WAY_SELECTIVE
  Existing canonical shape.

JOIN_3WAY_SELECTIVE_COVERING
  Identical SQL and cardinality, but the fixture additionally creates:
    ORDER(customer_id, id)
    LINE(order_id, id)

These indexes contain the join key plus the selected table id, allowing ORDER
and LINE to be satisfied index-only when selected by the optimizer.

All six SERVER engines receive the same additional indexes.

Interpretation
--------------
If Gen2/PostgreSQL closes materially on the covering workload, non-covering
base-row materialization remains important.

If the PostgreSQL advantage remains similar even when the inner legs become
covering/index-only, the residual gap is primarily shared relational execution
(join/projection/generated-row machinery), not MVCC base fetching.

Diagnostic only. No production engine, optimizer, storage, WAL/recovery,
durable-format, or benchmark-threshold changes.
