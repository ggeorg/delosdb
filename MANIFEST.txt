F08-T preframed WAL append experiment

Production experiment (default OFF):
- delosdb.experimental.rawStorePreframedLogAppend.enabled=true
- Each private FileLogger assembles the physical WAL record wrapper before entering LogToFile.
- LogToFile retains authoritative global ordering, LogInstant allocation, checksum reservation,
  file switching, shared buffering, flush/sync, replication and recovery semantics.
- Inside the shared append monitor the prepared path patches the authoritative 8-byte instant
  and performs one contiguous copy into the existing LogAccessFile buffer.

Focused verification:
- runPreparedLogRecordFrameTest validates the exact physical wrapper layout and buffer reuse.

Benchmark:
- runDelosF08RawStorePreframedLogAppendServerJfr
- PRIMARY_KEY_ONLY INSERT_100, payload=16, clients=8, 4 runs.
- Heap + Gen2-status enable the experiment; upstream Derby remains unchanged.
- 1 MiB RawStore log buffer + durability=test isolate in-memory append serialization.
- Server JFR uses JavaMonitorEnter threshold=1 us.
