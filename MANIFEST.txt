DelosDB B-tree insert root routing
==================================

Purpose
-------
Stop every B-tree insert from taking the index root's exclusive latch.
With insert lanes and the held-intent regrant, PK and INDEXED inserts are
bound by B-tree page latches, the root first: every insert latched it and
coupled to the child. Inserts now route through the immutable root routing
snapshot that keyed reads already use, latch the child while holding
nothing, and re-check the snapshot (review doc section H, rule 1).

Changes
-------
- BTreeController.findInsertLeaf: the root routing snapshot is on by
  default (-Ddelosdb.btree.insertRootRoutingSnapshot.disabled=true restores
  the latched-root descent). A missing or changed snapshot falls back to
  the latched descent, which republishes it. Hit and fallback counters.
- ControlRow.observe{Root,Branch,Leaf}RoutingSnapshot: a change of snapshot
  owner invalidates the previous owner's snapshot. One index can have
  several live BTree instances: each root control row decodes its own, so
  after the root page is reloaded, logical undo (B2IUndo) and plans
  compiled after a conglomerate cache miss use a new instance while cached
  conglomerates and older plans keep the old one. A page change invalidated
  only the current owner, leaving the other instance routing on stale
  separators. With inserts routed this way, rows went to leaves that do not
  cover their keys (index order corruption, or an endless insert/split
  loop). Keyed reads, which already use the snapshot on main, are exposed to
  the same mechanism.
- InsertRootRoutingTestSupport (test bridge) and
  InsertRootRoutingSnapshotTest: 8 writers inserting shuffled keys into a
  wide-key index with committed and rolled-back batches, then index order,
  a point lookup per key and SYSCS_CHECK_TABLE; a second BTree instance
  forced by page and conglomerate cache pressure, inserting through both
  plans across splits.

Deliberately unchanged
----------------------
- Branch routing snapshots (still experimental and off), split and undo
  paths (canonical latched descent), latch and lock order, on-disk format,
  WAL, recovery

Qualification
-------------
- Embedded insert probe, 8 writers, rare log switch, 3 alternating pairs:
  PK 369k vs 286k rows/s (+29%); INDEXED 169k vs 149k (+13%); BARE (no
  index) unaffected within noise.
- InsertRootRoutingSnapshotTest 8/8 repeat runs plus the suite run. Without
  the owner invalidation the concurrent test fails with a sanity assert
  (last row on a left leaf greater than the first row on its right sibling)
  and the second-instance test loops until its timeout.
- derbyStoreTests 435/435. delosRecoveryTests 57/57.
- delosConcurrencyTests 58: DEL-ISO-001, DEL-FK-004 and the task-only
  F08TransactionStatus test fail as on main; DEL-TRAVERSAL-001 and
  BTreeIndexConcurrencyArchitectureProofTest pass.
