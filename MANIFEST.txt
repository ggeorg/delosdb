DelosDB Gen2-C3 F05 row-production control overlay

Purpose
-------
Separate F05 three-way relational execution from result-row production /
wire-consumption cost across the full SERVER engine matrix.

Diagnostic workloads
--------------------
JOIN_3WAY_SELECTIVE
  Existing canonical query returning 1200 rows:
    c.id, o.id, l.id

JOIN_3WAY_SELECTIVE_AGGREGATE
  Same joins, same predicates, and consumes all three ids, but returns one row:
    count(*), sum(c.id), sum(o.id), sum(l.id)

Both workloads use the same multi-join fixture, indexes, deterministic Delos
statistics refresh, Gen2-C3 read architecture, physical scan cost, and
physical RowLocation cost.

Interpretation
--------------
If PostgreSQL's advantage shrinks materially on the aggregate control, a
large part of the canonical gap is row production / JDBC / protocol work.

If the PostgreSQL advantage remains similar, the gap is primarily relational
execution below result production.

Diagnostic only. No production engine, storage, optimizer, WAL/recovery,
durable-format, or benchmark-threshold changes.
