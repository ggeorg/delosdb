DelosDB Gen2-C3 F05 B-tree start-search parameter reuse A/B overlay

Purpose
-------
Falsify whether repeated B-tree scan-start allocation materially contributes
to the remaining matched-plan F05 selective-join gap.

Evidence
--------
The current matched forced plan performs:
  ORDER index scan opens = 100
  LINE  index scan opens = 400

Latest equal-duration JFR attributes ~70% of sampled Gen2 allocation pressure
to:
  BTreeScan.positionAtStartForForwardScan(...)

That method currently allocates a new SearchParameters for every scan start.

SearchParameters itself documents that it is intended to be reusable.

Experiment
----------
OFF by default:
  existing allocation on every scan start

ON:
  -Ddelosdb.experimental.btreeReuseStartSearchParameters=true

When enabled, each BTreeScan instance retains one SearchParameters object and
resets its mutable search/result fields before each start-position search.

This is diagnostic only. Do not promote directly from this overlay.

No changes
----------
No MVCC visibility or storage semantics.
No optimizer costing or join strategy changes.
No benchmark thresholds or semantic-oracle changes.
No RawStore WAL/recovery or durable-format changes.
