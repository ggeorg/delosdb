DelosDB Gen2-C3 F05 covering plan decomposition overlay

Purpose
-------
Prove whether the large six-engine throughput gain from adding covering
ORDER(customer_id,id) and LINE(order_id,id) indexes is caused by eliminating
INDEX_TO_BASE_ROW, rather than by an unrelated optimizer/join-plan change.

Captured variants
-----------------
Heap and Gen2-C3:
- natural non-covering
- forced indexed/NL non-covering
- natural covering
- forced indexed/NL covering

For each variant the diagnostic writes EXPLAIN and EXPLAIN ANALYZE and
summarizes:
- INDEX_TO_BASE_ROW node count
- INDEX_SCAN node count
- HASH join count
- NESTED LOOP count
- total openMillis
- total nextMillis

All variants must produce the same semantic fingerprint.

Diagnostic only. No production SQL engine, storage, optimizer, WAL/recovery,
durable-format, or benchmark-threshold changes.
