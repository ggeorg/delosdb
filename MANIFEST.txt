DelosDB Gen2-C3 F05 batched base-fetch reachability fix

Purpose
-------
Make Phase-2D explicitly use CLOSE_CURSORS_AT_COMMIT so the new bounded
INDEX_TO_BASE_ROW batch experiment is actually reachable.

Root cause
----------
IndexRowToBaseRowResultSet enables the diagnostic batch path only for a
non-holdable result set.

Phase-2D previously used openPhase2AConnection(), which leaves Derby's default
HOLD_CURSORS_OVER_COMMIT unchanged. Therefore the prior "batch ON" report did
not exercise AccessMethodBaseFetchBatch at all.

Change
------
Only Phase-2D connections now explicitly use:
  ResultSet.CLOSE_CURSORS_AT_COMMIT

The summary records:
  benchmarkHoldability=CLOSE_CURSORS_AT_COMMIT

Why two measurements are required
---------------------------------
Cursor holdability itself can affect DelosDB read-path reachability. Compare:
1. scalar/OFF with CLOSE_CURSORS_AT_COMMIT
2. batch/ON with CLOSE_CURSORS_AT_COMMIT

Do not compare the new ON measurement directly to the previous default-
holdability Phase-2D result.

Scope
-----
Diagnostic harness only.
No production SQL engine, MVCC, RawStore, optimizer, WAL/recovery, durable
format, benchmark thresholds, or semantic-oracle changes.
